# DNS Configuration Guide for arthainvestcapital.com

## Overview

This guide explains how to configure DNS records to point your domain to the production server.

---

## 🌐 DNS Records Required

### **1. A Record (Primary Domain)**

**Purpose:** Point domain to server IP address

| Field | Value |
|-------|-------|
| Type | A |
| Name | @ (root) |
| Value | YOUR_SERVER_IP |
| TTL | 3600 (1 hour) |

**Example:**
```
@ A 203.0.113.42
```

### **2. A Record (www Subdomain)**

**Purpose:** Point www subdomain to same server

| Field | Value |
|-------|-------|
| Type | A |
| Name | www |
| Value | YOUR_SERVER_IP |
| TTL | 3600 |

**Example:**
```
www A 203.0.113.42
```

### **3. CNAME Records (Optional)**

**Purpose:** Create additional subdomains

| Field | Value |
|-------|-------|
| Type | CNAME |
| Name | api |
| Value | arthainvestcapital.com |
| TTL | 3600 |

| Field | Value |
|-------|-------|
| Type | CNAME |
| Name | dashboard |
| Value | arthainvestcapital.com |
| TTL | 3600 |

### **4. MX Records (Email - Optional)**

**Purpose:** Route emails to mail server

| Field | Value |
|-------|-------|
| Type | MX |
| Name | @ |
| Priority | 10 |
| Value | mail.arthainvestcapital.com |
| TTL | 3600 |

### **5. TXT Records (Verification & Security)**

**For Let's Encrypt Verification:**
```
Type: TXT
Name: _acme-challenge
Value: (generated by certbot)
TTL: 600
```

**For SPF (Email Security):**
```
Type: TXT
Name: @
Value: v=spf1 mx ~all
TTL: 3600
```

**For DMARC (Email Authentication):**
```
Type: TXT
Name: _dmarc
Value: v=DMARC1; p=quarantine; rua=mailto:admin@arthainvestcapital.com
TTL: 3600
```

## 🔧 DNS Provider Setup Instructions

### **GoDaddy**

1. Log in to GoDaddy.com
2. Go to **Domains** → your domain
3. Click **Manage DNS**
4. Find **Records** section
5. For **A Records:**
   - Find existing record for `@`
   - Click **Edit**
   - Change Value to your server IP
   - Save
   - Add new record for `www`:
     - Type: A
     - Name: www
     - Value: YOUR_SERVER_IP
     - Click Add
6. Wait 10-15 minutes for propagation

### **Namecheap**

1. Log in to Namecheap.com
2. Go to **My Products** → Domain List
3. Click **Manage** next to your domain
4. Go to **Advanced DNS** tab
5. In **Host Records** section:
   - Edit `@` record (or @):
     - Type: A
     - Value: YOUR_SERVER_IP
     - TTL: 3600
     - Save
   - Add new record:
     - Type: A
     - Host: www
     - Value: YOUR_SERVER_IP
     - TTL: 3600
     - Save
6. Changes propagate in 10-15 minutes

### **CloudFlare**

1. Log in to CloudFlare.com
2. Select your domain
3. Go to **DNS** tab
4. Add/Edit A records:
   - Record 1:
     - Type: A
     - Name: @
     - IPv4 address: YOUR_SERVER_IP
     - Proxy: DNS only (gray cloud)
     - TTL: Auto
   - Record 2:
     - Type: A
     - Name: www
     - IPv4 address: YOUR_SERVER_IP
     - Proxy: DNS only
     - TTL: Auto
5. For SSL certificate:
   - Go to **SSL/TLS** → **Edge Certificates**
   - Ensure "Always Use HTTPS" is enabled
   - Use "Full" encryption mode

### **AWS Route 53**

1. Log in to AWS Console
2. Go to Route 53 → Hosted zones
3. Select your domain
4. Click **Create record**
   - Record name: (leave blank for @)
   - Type: A
   - Value: YOUR_SERVER_IP
   - TTL: 300
   - Click Create records
5. Repeat for www subdomain

### **Google Domains**

1. Log in to Google Domains
2. Select your domain
3. Click **DNS** (left sidebar)
4. Scroll to **Custom records**
5. Add records:
   - Type: A
   - Name: @
   - Data: YOUR_SERVER_IP
   - Add
   - Type: A
   - Name: www
   - Data: YOUR_SERVER_IP
   - Add
6. Wait for propagation (can be instant)

### **1&1/Ionos**

1. Log in to Ionos.com
2. Go to **Domains** → your domain
3. Click **Edit DNS Settings**
4. Find A records section
5. Edit/Add records:
   - @ = YOUR_SERVER_IP
   - www = YOUR_SERVER_IP
6. Save and wait for propagation

## 🔒 SSL/TLS Certificate Setup

After DNS is configured, set up SSL certificate for HTTPS.

### **Using Let's Encrypt (Recommended)**

```bash
# SSH into server
ssh deploy@arthainvestcapital.com

# Stop any service using port 80/443
docker-compose down

# Install Certbot (Ubuntu/Debian)
sudo apt-get update
sudo apt-get install certbot python3-certbot-nginx

# Generate certificate
sudo certbot certonly --standalone \
  -d arthainvestcapital.com \
  -d www.arthainvestcapital.com

# Certificate will be at:
# /etc/letsencrypt/live/arthainvestcapital.com/

# Copy to project ssl directory
sudo cp /etc/letsencrypt/live/arthainvestcapital.com/fullchain.pem ssl/arthainvestcapital.com.crt
sudo cp /etc/letsencrypt/live/arthainvestcapital.com/privkey.pem ssl/arthainvestcapital.com.key
sudo chown $USER:$USER ssl/*

# Restart containers
docker-compose up -d

# Verify certificate
openssl x509 -in ssl/arthainvestcapital.com.crt -text -noout
```

### **Auto-Renewal (Automatic)**

```bash
# Add cron job for auto-renewal
sudo crontab -e

# Add this line (runs daily at 2 AM)
0 2 * * * certbot renew --quiet && docker-compose restart nginx
```

## ⏱️ DNS Propagation Timeline

| Time | Status |
|------|--------|
| 0 min | DNS changes submitted |
| 5-30 min | Most servers updated |
| 1-4 hours | Global propagation |
| 24-48 hours | Guaranteed full propagation |

**Note:** TTL setting affects propagation speed:
- Lower TTL = Faster propagation (but more server load)
- Higher TTL = Slower propagation (but less server load)

For deployment: Use TTL of 3600 (1 hour) for balance.

## 🆘 Troubleshooting

### **"Domain not resolving"**

**Solution:**
1. Wait 10-15 minutes (DNS caching)
2. Clear local DNS cache:
   ```bash
   # macOS
   sudo dscacheutil -flushcache
   
   # Windows (PowerShell as admin)
   ipconfig /flushdns
   
   # Linux
   sudo systemctl restart systemd-resolved
   ```
3. Test with different DNS: `nslookup arthainvestcapital.com 8.8.8.8`
4. Verify A record in DNS provider settings

### **"SSL certificate error"**

**Solution:**
1. Verify certificate files exist: `ls -la ssl/`
2. Check certificate validity: `openssl x509 -in ssl/arthainvestcapital.com.crt -text`
3. Ensure domain name matches in certificate
4. Wait for Let's Encrypt if just issued

### **"Connection refused / timeout"**

**Solution:**
1. Verify server IP is correct: `ssh deploy@arthainvestcapital.com`
2. Check application is running: `docker-compose ps`
3. Check firewall allows ports 80/443: `sudo ufw status`
4. Enable ports: `sudo ufw allow 80/tcp && sudo ufw allow 443/tcp`

### **"Wrong IP or old DNS cache"**

**Solution:**
```bash
# Flush local cache (see above)

# Check propagation globally
nslookup arthainvestcapital.com 1.1.1.1  # Cloudflare DNS
nslookup arthainvestcapital.com 8.8.8.8  # Google DNS
nslookup arthainvestcapital.com 208.67.222.222  # OpenDNS

# All should show correct IP
```
